# Docs 작성 규칙

- 목적과 결론을 첫 문단에 요약한다.
- 짧은 문장, 짧은 단락을 유지하고 목록을 적극 활용한다.
- 현재 시제를 사용하고 불필요한 수식어를 피한다.
- 파일당 한 가지 주제만 다루고, 관련 문서가 있으면 링크를 남긴다.
- 예시나 코드가 필요할 때만 fenced code block을 사용한다.
- 문서 저장 전 맞춤법 검사 한 번으로 마무리한다.

## 네이밍과 구조

- 모든 문서는 소문자-케밥케이스(`agent-architecture.md`)로 저장한다.
- 배경/목표는 `*-overview.md`, 상세 절차는 `*-guide.md`, 의사결정 기록은 `*-adr-001.md`처럼 접미사를 구분한다.
- 동일 주제의 문서는 폴더를 만들어 그룹화하고, 인덱스 파일(`README.md`)에 하위 문서를 링크한다.
- 작성일이나 버전이 중요하면 파일명에 `2024-03-18` 형태의 날짜를 포함한다.
